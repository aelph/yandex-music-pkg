# Yandex Music на системном Electron

`PKGBUILD` для Arch/Manjaro: Яндекс Музыка поверх **системного `electron42`**
вместо встроенного Electron из официального deb. Сборка чистая, отслеживается
`pacman`, работает в нативном Wayland с корректной тенью окна.

Пакет называется **`yandex-music-system-electron`** и никак не связан с пакетом
`yandex-music` из AUR (от которого он когда-то произошёл): AUR-помощники не
предлагают для него «обновлений». Благодаря `provides`/`conflicts` он штатно
заменяет установленный `yandex-music` и удовлетворяет зависимости от него.

## На чём основано

- **Код приложения** — официальный deb Яндекса; из него берётся `app.asar`.
- **Среда выполнения** — системный `electron42` (репозиторий `extra`). Встроенный
  Electron из deb не используется: он старее и в Wayland-сессии не рисует тень
  безрамочному окну (CSD-тень для frameless-окон появилась только с Electron 41).
  На `electron42` тень есть.
- **Распаковка** — `bsdtar` (libarchive), без `alien`, `dpkg`, `rpm`.

## Состав пакета и назначение частей

`PKGBUILD` собирает пакет так:

- **Версия — динамически из фида `latest-linux.yml`.** На каждой пересборке
  `makepkg` тянет актуальный deb, `pkgver()` подхватывает номер — ручной правки
  версии не требуется.
- **Контроль целостности** — sha512 из того же фида.
- **`/opt/yandex-music/app.asar`** (и `app.asar.unpacked`, если он есть) — код
  приложения.
- **`/opt/yandex-music/assets`** (`icon.ico`, `icons/icon_*.png`) — иконки трея;
  код приложения ищет их по `process.resourcesPath/assets`.
- **`/opt/yandex-music/package.json`** — делает каталог приложением, чтобы Electron
  нативно взял из него:
  - **имя** `YandexMusic` → профиль `~/.config/YandexMusic` (куки и сессия);
  - **версию** → валидный semver (приложение проверяет её при старте).
- **`/opt/yandex-music/launcher.js`** (`main` каталога-приложения) — тонкий шим.
  До загрузки `app.asar` переопределяет два пути:
  - `process.resourcesPath` → `/opt/yandex-music` — чтобы нашлись иконки трея
    (иначе путь указывает в каталог самого Electron);
  - `app.getAppPath()` → `app.asar` — чтобы нашёлся web-контент из `app/` внутри
    asar.

  Кроме того, расставляет кнопки окна так же, как в системе. На Linux окно без рамки, а кнопки рисует веб-страница — всегда справа. Шим читает раскладку кнопок (KDE — `ButtonsOnLeft`/`ButtonsOnRight` из `kwinrc`, иначе — `button-layout` из `gsettings`) и внедряет CSS, переставляющий кнопки заголовка. Раскладка читается при запуске.
- **`/usr/bin/yandex-music`** — обёртка `electron42 /opt/yandex-music`. Флаг
  Wayland не нужен: нативный режим включается автоопределением.
- **`.desktop`-ярлык и иконки приложения** в `hicolor`.

## Что работает

- Чистая сборка на системном Electron, отслеживаемая `pacman` (≈300 МБ меньше —
  ушёл дублирующий встроенный Electron).
- Нативный Wayland и тень окна.
- Иконка в системном трее и контекстное меню.
- Воспроизведение (поток через ALSA, проверено на 176,4 кГц).
- MPRIS — управление из медиаплеера в системном лотке.

## Установка

```
cd ~/projects/yandex-music-pkg   # каталог с PKGBUILD
makepkg -si
```

## Обновление

Всё делает `./update.sh`:

- `./update.sh check` — сравнить установленную версию с фидом. Код возврата 10 —
  доступно обновление.
- `./update.sh` — если вышла новая версия: `makepkg -si` (свежий deb из фида,
  `pkgver` в `PKGBUILD` правит сам `makepkg`), проверка установленной версии,
  коммит `Update <версия>`.
- `./update.sh rollback [версия]` — откат на ранее собранный локальный пакет.
  Собранные `.pkg.tar.zst` намеренно остаются в каталоге: пересобрать старую
  версию нельзя, фид отдаёт только latest.
- `./update.sh notify` — тихая проверка с уведомлением через `notify-send`; при
  недоступности сети завершается молча.

### Уведомления о новых версиях

Ежедневную проверку выполняет systemd-таймер пользователя (юниты в
`~/.config/systemd/user/`):

```
systemctl --user enable --now yandex-music-update-check.timer
```

Когда выходит новая версия, на рабочий стол приходит уведомление; дальше —
зайти в каталог и запустить `./update.sh`.

> Сборка всегда «latest»: фид указывает на самую свежую версию, поэтому собрать
> через этот `PKGBUILD` конкретную старую версию нельзя.
