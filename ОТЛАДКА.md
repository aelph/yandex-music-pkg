# Журнал отладки и подводные камни

Здесь собрано то, чего нет в `README.md`: почему принято каждое решение, какие
были тупики и как они разрешились. Полезно при пересборке и при переносе подхода
на другие Electron-приложения, запускаемые поверх системного Electron.

## 1. Зачем вообще системный Electron (тень окна)

Исходно использовался AUR-пакет `yandex-music` со встроенной копией Electron
внутри `/opt/yandex-music` (бинарь `yandexmusic`): Electron 38, Chromium 140. На
этой сборке безрамочное окно **не получало тень** в сессии Plasma Wayland.

Причина: KWin на Wayland по умолчанию предлагает серверное оформление (SSD), а
приложения с собственным заголовком (как Yandex Music) рисуют клиентское
оформление (CSD) и тень рисуют сами. До Electron 41 frameless-окна вообще не
поддерживали CSD на Wayland — поддержка (включая собственную тень) появилась с
Electron 41. Встроенный Electron 38 в эту границу не попадал.

Запуск того же `app.asar` на системном `electron42` (версия 42.3.0) даёт окно с
тенью. Отсюда всё решение: брать из официального deb только `app.asar` и
запускать его на системном Electron.

### Матрица «версия Electron → тень / трей»

| Electron        | Тень | Иконка в трее |
|-----------------|------|---------------|
| 38 (встроенный) | нет  | да¹           |
| 39 (системный)  | нет  | нет²          |
| 42 (системный)  | да   | да³           |

- ¹ У встроенного бинаря ассеты лежали по «правильному» для него `resourcesPath`.
- ² На 39 иконка не появлялась по тому же корню, что описан в §2 (пустой путь к
  ассетам), а тень при этом отсутствует.
- ³ После исправления пути к ассетам (§2). До исправления иконки на 42 не было.

## 2. Иконка трея: пустой квадрат

**Симптом.** Место под иконку в трее есть, контекстное меню и клики работают,
но изображение не отрисовывается — пустой квадрат.

**Корень.** Код трея в `app.asar` (`/index.js`) строит путь к иконке от
`process.resourcesPath`:

```js
const createPngIcon = () => {
  const sizes = [22, 24, 32, 48, 16];
  const iconsPath = path.join(process.resourcesPath, "assets", "icons");
  // перебор icon_${size}x${size}.png → мультиразмерный nativeImage
};
```

При запуске приложения системным Electron `process.resourcesPath` равен каталогу
**самого Electron** (`/usr/lib/electron42/resources`), а не `/opt/yandex-music`.
Проверено напрямую:

```
$ electron42 -e 'console.log(process.resourcesPath)'
/usr/lib/electron42/resources
```

Файлов `assets/icons/icon_*.png` там нет → `nativeImage.createFromPath` возвращает
пустое изображение → `Tray` создаётся, меню работает, а картинки нет.

> **Важно про прежний ошибочный вывод.** Раньше проблему относили к багу
> публикации SNI в `electron42`: `GetAll` живого объекта `StatusNotifierItem`
> показывал `Menu`/`Status`, но не `IconPixmap`. На деле это **следствие** пустого
> `nativeImage`: когда у `Tray` нет валидного изображения, Electron нечего
> выставлять в `IconPixmap`. Это не отдельный баг Electron, а тот же пустой путь к
> ассетам. Упаковочными средствами чинится.

**Решение.** Положить `assets` в `/opt/yandex-music` (уже делается в `package()`)
и переопределить `process.resourcesPath` на `/opt/yandex-music` до загрузки
`app.asar` — это берёт на себя `launcher.js`. Свойство `process.resourcesPath`
помечено `writable:false`, но `configurable:true`, поэтому переопределяется через
`Object.defineProperty`. После этого `nativeImage` непустой (проверено: итоговая
иконка `22×22`, `isEmpty()===false`), и иконка отрисовывается.

## 3. Почему `/opt/yandex-music` — каталог-приложение, а не просто `app.asar`

Запускать `electron42 /opt/yandex-music/app.asar` напрямую нельзя по двум
причинам, обе всплыли по ходу.

### 3.1. Профиль и разлогин (`userData`)

Имя приложения определяет каталог профиля `~/.config/<name>`, где лежат куки и
сессия. Приложение само `app.setName()` не вызывает, поэтому имя берёт Electron:

- запуск `app.asar` (рядом `package.json` с `"name":"YandexMusic"`) →
  `~/.config/YandexMusic`;
- запуск одиночного `launcher.js` (рядом нет `package.json`) → имя по умолчанию
  `Electron` → `~/.config/Electron` → **другой профиль, то есть разлогин**.

Лечить это вызовом `app.setName('YandexMusic')` в шиме **нельзя**: имя/профиль он
поправит, но в рантайме это ломает загрузку контента (см. §3.2).

### 3.2. `setName`/`setVersion` в рантайме ломают контент

Попытка выставить имя и версию из шима приводила к ошибке загрузки
`music-application://desktop` (`ERR_FAILED (-2)`). A/B-прогон подтвердил
воспроизводимо: без `setName`/`setVersion` контент грузится, с ними — нет.

### 3.3. Версия и semver

Без `package.json` рядом с точкой входа `app.getVersion()` отдаёт `"0.0"`, и
приложение падает:

```
Error App version is not a valid semver version: "0.0"
```

(При запуске одиночного файла версия по умолчанию вообще бралась от самого
Electron — `42.3.0` — и иногда «случайно» проходила, что путало картину.)

### Итог

Все три пункта закрываются нативно, если сделать `/opt/yandex-music` каталогом
приложения со своим `package.json`:

```json
{ "name": "YandexMusic", "version": "<pkgver>", "main": "launcher.js" }
```

Тогда Electron сам берёт имя (правильный профиль) и версию (валидный semver), без
проблемных рантайм-вызовов. А `launcher.js` остаётся тонким шимом и правит только
два пути:

```js
'use strict';
const APP_DIR = '/opt/yandex-music';
const ASAR = APP_DIR + '/app.asar';
const { app } = require('electron');

Object.defineProperty(process, 'resourcesPath', { value: APP_DIR, configurable: true });
Object.defineProperty(app, 'getAppPath', { value: () => ASAR, configurable: true });

require(ASAR);
```

`app.getAppPath()` правится потому, что при запуске каталога он по умолчанию
вернул бы `/opt/yandex-music`, а приложение ищет web-контент в `getAppPath()/app`
— то есть внутри `app.asar`.

## 4. Повреждённый профиль после неудачных запусков

Падающие запуски (версия `"0.0"`, аварийные завершения) повредили существующий
профиль `~/.config/YandexMusic`: даже корректная сборка упиралась в `ERR_FAILED`
при загрузке контента, тогда как на чистом профиле всё грузилось. Лечение —
удалить испорченный и мусорный профили и войти заново:

```
rm -rf ~/.config/YandexMusic ~/.config/Electron
```

## 5. Конфликт файлов при установке

Если в `/opt/yandex-music/assets` остались файлы от прежнего, не отслеживаемого
`pacman` билда, установка падает с «конфликтующими файлами» (`pacman -Qo` по ним
отвечает «ни один пакет не содержит»). Разовое лечение — отдать их во владение
пакету при установке:

```
sudo pacman -U --overwrite '/opt/yandex-music/*' yandex-music-*-x86_64.pkg.tar.zst
```

После этого файлы трекаются пакетом и конфликт больше не возникает.

## 6. Несущественные сообщения при запуске

В stderr на системном Electron встречаются и к делу не относятся:

- `qtpaths: command not found` — отсутствует Qt5-утилита, на работу не влияет.
- `Failed to load module "appmenu-gtk-module"` — глобальное меню GTK, не трей.
- `wayland_wp_color_manager … Unable to set image transfer function` — побочный
  шум нативного Wayland; заодно служит индикатором, что Electron запущен именно в
  нативном Wayland, а не через XWayland.
